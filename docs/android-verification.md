APK9で、アプリ内の説明を読み、使用状況のAndroid設定を開き、再生モードを選び、ユーザー補助と通知アクセスを各説明から設定し、Chromeを選択しました。再生時間が増えることを確認しました。説明前にサービス設定ボタンを押す経路については、APK8で説明画面へ移り、両方の同意がfalseのままになることを確認しています。この導線のソースはAPK9でも同じです。

## 配布署名経路（2026-10-10）

`pack-release` の作成経路をWindowsのAndroid SDK 36.1.0で検証しました。製品の秘密鍵は使用せず、試験専用の使い捨てRSA 3072bit鍵で確認しました。下の結果は署名とパッケージの検査であり、端末での更新インストール成功を示しません。

| 確認 | 結果 |
|---|---|
| 同じ鍵でversionCode 3と4のAPKを作成 | 両方の証明書が、署名前の証明書ファイルから確認したSHA-256と一致 |
| APKの設定 | versionCode・versionNameが指定値。デバッグ不可。権限はPACKAGE_USAGE_STATSのみ |
| APKの署名と配置 | apksignerの検証成功、zipalignの16KB配置検査成功 |
| 別の証明書SHA-256を指定 | 作成失敗。完成品のrelease.apkなし |
| Android Debug証明書とその正しいSHA-256を指定 | デバッグ証明書として拒否。完成品のrelease.apkなし |

署名経路ができたことを、製品用の署名鍵の保管・広告付き配布版・公開サイト・実端末での更新・iOS対応の完了に読み替えません。

時計の変更を阻止しません。再生の最初の約1秒や、観測間隔が3秒を超えた区間は加算しないため、再生時間は少なめになる場合があります。
